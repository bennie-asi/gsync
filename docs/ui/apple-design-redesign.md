# GSYNC「存档脉络」界面改版

## 范围与设计依据

GSYNC 是 WinUI 3 Windows 桌面端的游戏存档同步工具。此次方案以玩家能否看懂存档状态、知道下一步、避免误覆盖为首要目标，采用 Apple Human Interface Guidelines 的清晰、可访问、适应性和用户自主原则；窗口控制、字体、输入与键盘交互仍遵循 Windows 习惯。Stitch 画面是设计稿，示例游戏、时间与连接状态均为示意，不代表已实现或真实数据。

设计依据：本机安装的 `apple-design-skill` 中 `references/hig/accessibility.md`（Vision、Mobility）、`layout.md`（Visual hierarchy、Adaptability）、`typography.md`（Ensuring legibility）、`color.md`（Inclusive color）、`buttons.md`（Content、Role）、`feedback.md`（Best practices）、`entering-data.md`（Best practices）、`sidebars.md` 和 `dark-mode.md`。这些原则用于 Windows 设计，不将 macOS 专属组件照搬进 WinUI。

## 本次审视发现

1. 游戏库「检查并同步」实际先要求选择一个游戏并打开比较，不会直接完成同步。建议改为「比较存档」；批量上传放在次级操作中，提前说明远端变化会阻止上传。见 `src/GSYNC.App/Pages/HomePage.xaml.cs` 的 `CheckAndSyncButton_Click` 和 `SyncNowButton_Click`。
2. 详情页同时突出上传、下载、恢复和检查，容易让用户在理解方向之前选择覆盖操作。主操作应是比较；方向性写入与恢复进入次级操作，保留明确的确认和后果说明。
3. 冲突页需要在每条文件旁解释「保留本机」会写入目标、「保留目标」会覆盖本机，以及「暂不处理」不会更改该文件；无对应文件的选项不可用。显示已决定、未决定数量，允许仅处理已决定项目。时间戳只能作为上下文，不能单凭它判定哪份存档安全。
4. 目标状态需要区分未检查、检查中、最近一次检查成功和失败，并显示检查时间；不能把过期结果表述成实时在线。失败提示应带有重新测试或编辑凭据等恢复入口。
5. 添加游戏时，路径不存在的警告需要说明可能原因，并清楚区分返回编辑与继续保留配置。新建目标后应恢复向导输入；创建后检查远端不应表述成已完成首次同步。
6. 屏幕中存在 10–11 DIP 的辅助文字，例如设置页的属性标签和说明。建议将常规正文提高到 14 DIP、辅助信息至少 13 DIP，并随系统文字放大而换行；实际效果需在 WinUI 和 Windows 缩放设置下验证。
7. 队列中的等待、进行中、取消、完成和失败需要明确区分；加入队列不等于同步完成。仅显示已有能力：取消活跃任务、移除等待任务，不设计未实现的暂停或恢复。
8. 设置支持深色、浅色和默认的「跟随系统」选项，并保留已有用户选择。
9. 历史记录现保存执行时的目标名称和命名空间；迁移前的旧记录显示「目标未记录」，不再根据当前绑定推测过去的目标。
10. 比较页对所有差异文件默认显示「待选择」，包括仅存在于一端的新增文件。确认前汇总所选方向及影响，未选择的文件不处理。

## 视觉系统

以一条有文字标签的「本机 → 同步目标」存档脉络作为识别元素：它表达真实的两端和最近一次确认，而不是装饰性网络图。游戏封面仅辅助辨认，状态始终有文字和图标。移除重复警告、无意义数字、装饰性边框和持久的霓虹强调。

| 用途 | 深色 | 浅色 | 示例对比度 |
| --- | --- | --- | --- |
| 画布 / 主文字 | `#19222B` / `#F0F5F6` | `#F3F6F6` / `#192B32` | 14.63:1 / 13.49:1 |
| 内容面 / 次级文字 | `#25323D` / `#BAC7CC` | `#FFFFFF` / `#52666D` | 7.57:1 / 6.03:1 |
| 内容面 / 强调色 | `#25323D` / `#80CFCC` | `#FFFFFF` / `#006C6A` | 7.31:1 / 6.26:1 |
| 内容面 / 警告文字 | `#25323D` / `#FFD098` | `#FFFFFF` / `#855300` | 9.19:1 / 6.49:1 |

这些是设计稿色值；实际应用应优先使用能响应 Windows 高对比度和主题变化的语义资源，并在所有文字、图标和控件状态上重新测试对比度。按钮在深色强调背景 `#80CFCC` 上使用 `#19222B` 文字，对比度 8.98:1。

字体使用 Segoe UI Variable 和微软雅黑回退，路径可用 Cascadia Mono；标题 24/30、分组标题 16/22、正文 14/20、辅助 13/18 DIP。采用 8 DIP 间距节奏、8 DIP 圆角和 32–40 DIP 控件高度，保留明显的键盘焦点、悬停、按下及禁用状态。动效只在状态变化时轻微提示，遵守减少动画设置。

常规宽度：

```text
┌ Windows 标题栏 ──────────────────────────────────────────┐
│ 导航     │ 游戏库                         添加游戏       │
│ 游戏库   │ 搜索 / 筛选                                  │
│ 同步目标 │ 游戏与状态     本机 → 同步目标    比较存档   │
│ 变量     │ 游戏与状态     最近确认时间       查看详情   │
│ 历史     │                                                │
│ 队列     │                                                │
│ 设置     │                                                │
└──────────┴───────────────────────────────────────────────┘
```

紧凑宽度：

```text
┌ Windows 标题栏 ──────────────────┐
│ 菜单  游戏库         添加游戏   │
│ 搜索                            │
│ 筛选 / 排序                     │
│ 游戏名与状态                    │
│ 本机 → 同步目标                 │
│ 最近确认时间        比较存档    │
└─────────────────────────────────┘
```

宽窗口可并排列表和详情；窄窗口将详情改为可返回的视图或纵向分组，保留全部功能。不要将关键状态和操作只放在窗口底边。行高应随语言和文字放大增长，而不是裁切。

## 关键流程

1. **首次配置**：选择来源、游戏与需要同步的内容；检查本机路径；选择或新建目标；核对摘要。路径警告允许用户修改或知情后继续。若选择创建后检查远端，目标已有文件时进入比较；目标为空且本机有文件时询问是否加入首次上传队列。
2. **比较与处理**：显示两端的客观文件信息和每个文件的选择；应用前汇总写入目标、覆盖本机与暂不处理的数量。确认后显示已加入队列，最终结果以实际任务记录为准。比较结果过期时停止处理并要求重新比较。
3. **目标失败**：显示最近一次检查失败的时间和可理解的原因，提供重新测试与编辑入口；未测试不能显示成功。移除目标前说明关联游戏受影响，本机和远端现有文件不会因移除目标配置而删除。
4. **历史与恢复**：旧记录不推测执行时的目标。仅列出真正存在的本机快照，恢复前说明受影响文件并要求确认；系统会先为当前受影响文件创建快照。
5. **队列**：只按真实任务状态显示等待和执行；有实际文件数时显示已处理/总数，否则显示进行中。活跃任务可请求取消，等待任务可移出队列；不虚构速度、剩余时间或暂停功能。

## 交互与实现验收

- 比较页显示来源、目标、比较时间、逐文件状态和处理方向；未决项目不被处理。比较后文件发生变化时停止应用并提示重新比较。
- 恢复快照前展示所选游戏、快照时间、受影响的本机文件和取消操作；只承诺实际实现提供的备份与恢复能力。
- 检查目标、同步和恢复都显示真实进度或不确定进度，成功、失败与取消由真实结果驱动；错误说明原因及下一步。
- 新增目标、切换来源、路径错误、搜索无结果、空游戏库、目标失败、无历史和空队列都要提供可继续的路径。
- 先完成状态语义、覆盖确认、键盘焦点和文本缩放，再调整导航、布局、排版及动效。验证中英文、深浅色、高对比度、键盘及屏幕阅读器；覆盖普通和最小支持宽度、200% 文字放大、离线与冲突状态。
- WinUI 界面已实现并在隔离数据下检查主要页面和紧凑窗口；高对比度、屏幕阅读器及 200% 文字放大仍需在实际设置下继续验证。
