# GitHub 版本更新与 Windows 登录自启：设计说明

本文是对 [GSYNC 界面重新设计](apple-design-redesign.md) 的补充。这里的开关、更新器和状态都是**拟议设计**，并非已经实现的功能。界面沿用现有设计系统和 Windows 原生窗口交互；示例版本、时间和发行说明不代表真实发布信息。

## 设计依据

- 当前仓库的远端为 `github.com/bennie-asi/gsync`。`scripts/build.ps1` 和 `.github/workflows/release.yml` 为 `win-x64` 构建 `GSYNC-{Version}-win-x64.zip`，版本来自发布标签，支持带 `v` 前缀的标签。
- 应用项目设置 `WindowsPackageType=None`，属于非 MSIX 的 WinUI 程序；当前发布流程没有提供应用内更新器，也未在仓库中看到签名更新清单。ZIP 是目录形式的便携发布物，不应把它描述为现成的安装程序。参见 [Microsoft：分发未打包的 WinUI 3 应用](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/unpackage-winui-app)。
- 应用设置已有社区游戏清单来源及刷新设置，它们只影响游戏识别规则；本文的版本更新针对 GSYNC 程序本身，两者分组、状态和按钮均应分开。
- 当前 UI 设置模型中没有开机自启或应用更新的对应开关。下面描述的是待实现的行为和验收要求。

## 设置页面

在现有外观、语言、同步安全、社区游戏清单和日志设置之外增加两个分组：

1. **启动**：`开机自启`，默认关闭。说明为「登录 Windows 后启动 GSYNC」。自启不修改自动同步设置；用户已启用的自动拉取仍按其自身规则运行。默认打开正常主窗口，不假设存在托盘或静默启动功能。
2. **关于与更新**：显示运行中的真实版本、`GitHub Releases` 来源、`自动检查更新`、`检查更新`、最近一次检查的时间与结果，以及查看发行页的入口。拟议默认自动检查开启；只检查，不自动下载或安装。版本来自构建的 InformationalVersion，不能在产品界面写死示例版本。

普通状态只在设置页显示；发现更新时在设置入口或页面给出可忽略提示。检查本身不阻塞启动和同步。拟议在应用启动后检查，按上次检查时间限频，建议最多每天一次，失败后退避；用户手动检查不受该日频率限制，但需避免重复并发请求及遵守服务端限流。`稍后`关闭当前提示，不修改自动检查选项。当前只设计稳定版通道，无需提供只有一个选项的通道下拉框。

## 更新流程和状态

状态由真实结果驱动，检查失败不能显示为「已是最新」。发行说明来自对应 GitHub Release，显示不可信内容时按文本或安全的受限 Markdown 处理，不执行脚本或加载任意内容。

| 状态 | 界面与可用操作 |
| --- | --- |
| 尚未检查 / 正在检查 | 显示当前版本和检查状态；请求中禁用重复检查，展示不确定进度。 |
| 已是最新 | 显示本次成功检查时间和「已是最新」。 |
| 有新版本 | 显示当前版本、新版本、来源和发行说明；操作为「下载更新」「稍后」「查看 GitHub 发行页」。只在应用内更新满足下述信任与部署前提时提供「下载更新」；否则将主操作改为「前往 GitHub 下载」。 |
| 下载 / 校验中 | 显示真实字节进度；总大小未知时使用不确定进度。允许取消，取消后清理临时文件。下载完成前不显示「已验证」。 |
| 更新已就绪 | 仅在下载及所有必需校验成功后显示；允许「退出并更新」或「稍后」。明确更新需要退出并重启。 |
| 有同步任务 | 说明正在执行或等待的任务；提供「同步结束后提醒我」和「稍后」。不静默取消任务或触发新的同步，待队列安全结束后重新展示确认。 |
| 网络错误、超时或 GitHub 限流 | 显示可理解的原因、最近成功检查时间（如有）、「重试」和「前往 GitHub 发行页」。不要混淆错误与无新版本。 |
| 没有正式发行版或没有兼容的 x64 文件 | 分别说明「暂无正式发行版」或「此版本没有适用于 Windows x64 的更新包」，提供发行页入口；不尝试执行其他架构或名称不匹配的文件。 |
| 缺少可信校验信息、校验不符、下载或更新失败 | 停止自动替换；显示原因并提供重试、查看发行页和日志。若无法安全自动恢复，明确告知用户具体状态与手动恢复路径，不伪称恢复成功。 |

建议使用 GitHub 的公开 Releases API，默认查询 GitHub 提供的最新非草稿、非预发布版本；版本比较采用 SemVer，并同时兼容有无 `v` 标签前缀。发行标签自身带预发布后缀时也不得当作稳定版，即使发布者没有在 GitHub 上设置预发布标记；当前发布工作流允许预发布标签，但未显式设置该标记，实施时应补齐。若 `/latest` 返回的是此类标签，提示无法确定稳定版并提供发行页入口，或按明确的分页策略寻找有效稳定版。`latest` 使用 GitHub 的最新正式发行版语义，不保证按 SemVer 排序；如果日后要保证寻找语义版本最大值，应另行定义完整分页和选择策略。不能解析当前版本或发行标签时显示「无法比较版本」，并提供发行页入口，不擅自覆盖。参见 [GitHub Releases API](https://docs.github.com/en/rest/releases/releases#get-the-latest-release)。

## 应用内更新的实现前提

目前发布的是 ZIP，因此设计需要分两种实际状态：

- **现有发布流程可支持的基础路径**：查询版本并打开对应 GitHub 发行页，让用户自行下载适用的 ZIP，退出 GSYNC 后按发行说明手动更新。运行数据默认位于 `%APPDATA%\GSYNC`，但实际路径可能由 `GSYNC_DATA_ROOT` 覆盖；不能假设所有用户数据都位于程序目录之外，也不能在替换前删除任何存档或用户配置。
- **拟议的一键更新路径**：先增加独立更新辅助程序和发布端可信签名清单。客户端内置受信任的公钥，验证发行清单签名、目标版本和 ZIP 哈希，然后才解压与交由辅助程序替换。GitHub 返回的 `digest`（如存在）可用于检测文件与该摘要是否一致，但与下载同渠道取得的摘要本身不能证明发布者身份；缺失可信签名信息时降级为 GitHub 手动下载。

辅助程序需要等待客户端完全退出，对路径、目录权限、压缩包穿越和重解析点做检查；使用临时目录、备份和原子替换或等效的可恢复流程，并在中断、磁盘不足、文件占用、权限不足或启动失败时给出真实恢复结果。不能覆盖数据目录、用户配置、快照或存档；若安装位置与数据路径重叠或无法判定安全范围，应停止并引导手动处理。更新前必须核实同步队列已完成并在最后一次确认时冻结新任务；不得静默终止同步。重启后的版本以实际运行程序为准，启动失败不能宣称更新成功。实现时还需规划签名密钥轮换、辅助程序自身更新和旧版本兼容性；这些能力当前均未建立。

## Windows 登录自启

默认关闭；用户主动开启后，为**当前 Windows 用户**登记登录启动项，不需要也不应默认请求管理员权限。非打包应用可通过当前用户 Run 键或启动文件夹快捷方式实现；必须正确处理包含空格的真实可执行文件路径。它发生于用户登录 Windows 后，不是系统尚未登录时运行。参见 [Microsoft：未打包应用的登录启动激活](https://learn.microsoft.com/en-us/windows/apps/windows-app-sdk/applifecycle/applifecycle-rich-activation)。

开关状态应结合实际启动项读取，而不是仅依赖应用设置里的布尔值：

- 注册成功后显示开启；注册或移除失败时还原界面状态，显示原因与重试入口。
- 如果可可靠读取到 Windows 或组织策略禁用该启动项，显示「Windows 已禁用该启动项」并提供「打开 Windows 启动应用设置」。无法确定系统状态时显示「状态无法确认」，不能声称已经生效。
- 当前程序与自启登记路径不一致时，显示「启动路径不一致」及两条实际路径。旧路径可能不存在，也可能仍指向另一份程序，不能直接断定已失效；提供「使用当前位置」和「暂不处理」，只有用户确认后才改写登记。如果启动项被 Windows 禁用，应引导用户到系统设置管理，不得绕过禁用状态。
- 关闭开关只移除本程序为当前用户创建的启动项，不影响其他用户、其他程序或 Windows 的其他启动设置。

## 验收

- 设置页中社区规则更新与应用更新互不混淆；手动检查、自动检查开关、当前版本、无更新、无发行版、无兼容包、网络失败和限流都能区分。
- 验证 `v` 前缀、预发布版本、版本无法解析、无摘要、坏签名、哈希不符、恶意 ZIP 路径、中断下载、重复检查和离线；应用内更新的任何安全前提不满足时均不能自动替换。
- 验证同步运行、排队、新任务竞争、用户取消、进程未退出、文件占用、无权限、磁盘不足及中途断电；只在确认完成后报告成功，失败时按实际结果展示恢复情况和下一步。
- 验证首次注册、重复开关、Windows 禁用、策略限制、程序路径含空格、程序搬迁、多个 Windows 用户和注册失败；尊重用户原有同步配置。
- 验证中英文、深浅色、高对比度、键盘焦点、屏幕阅读器、文本放大、窗口缩放与长发行说明。设计稿示意状态不等于实现或通过测试。
